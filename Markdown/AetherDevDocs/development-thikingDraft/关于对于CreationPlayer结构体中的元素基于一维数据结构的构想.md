# 关于对于CreationPlayer结构体的一维数据结构的构想

- 之前在开发基于RISC-V的内核的时候，基于UART的串口通信协议中使用的是类似于二进制的数据结构对传入的数据进行解析
- 结构:0100010
- 每一位对应一个状态的开关
- 那么在此结构体中，我们是否也可以一使用类似的结构体方法进行玩家创建的信息存储与解析
- 此方法是否可以减少运算成本并提高运算效率
- 但是该结构中存在一个问题
- 对于一个玩家的账户创建有三种方法，
- 分别为离线账户、正版账户和第三方认证账户
- 对于这个情况我目前的设想是使用两位，离线和正版的判断用一位掩码，而是第三方账户单独一位
- 如果第三方的掩码为1,则直接停止检测后面的离线正版账户掩码的判断
